TASNEEF V10863 — SERVER RESILIENCE / SUPABASE UNHEALTHY FIX
===========================================================

المشكلة التي تعالجها النسخة
---------------------------
عندما تصبح خدمات Supabase (Database / PostgREST / Auth / Storage) بحالة Unhealthy،
كانت بعض أكواد النظام تعتبر فشل الطلب وكأنه نتيجة فارغة وتستبدل البيانات الموجودة بـ []،
فتختفي المشاريع والعمال والتكتات والسجلات مؤقتًا. كما كان هناك أكثر من تحميل كامل متكرر
عند فتح الإدارة، إضافة إلى تحديث شامل عند الفني كل 20 ثانية.

ما تم تعديله في V10863
----------------------
1) منع مسح البيانات عند فشل أي طلب من Supabase.
2) حفظ آخر نسخة ناجحة لكل مستخدم في IndexedDB داخل المتصفح.
3) إذا تعطل Supabase: تظهر آخر بيانات ناجحة بدل القوائم الفارغة.
4) شريط تنبيه واضح عند العمل على نسخة محفوظة، مع زر إعادة الاتصال.
5) إعادة المحاولة تلقائيًا كل 45 ثانية فقط أثناء وجود عطل، وليس بشكل هجومي.
6) عند رجوع السيرفر تتم المزامنة تلقائيًا وإخفاء التنبيه.
7) تقليل طلبات بدء التشغيل المتكررة في صفحة الإدارة إلى مسار تحميل واحد.
8) إيقاف التحديث الشامل للفني كل 20 ثانية؛ تحديث التكتات فقط عند قسم التكتات كل 60 ثانية.
9) تحميل الحضور لآخر 62 يومًا والسجلات للشهر الحالي في البداية بدل قراءة التاريخ الكامل كل مرة.
   التقارير والفترات الأخرى تستمر بالتحميل عند اختيار الفترة المطلوبة.
10) منع أكثر من تبويب على نفس الجهاز من تنفيذ تحميل كامل متزامن عندما توجد نسخة حديثة.
11) لا تغيير في شكل التقارير أو PDF أو الفلاتر أو بوابة العميل.

مهم جدًا
--------
النسخة تمنع اختفاء البيانات أثناء العطل وتخفف الضغط الذي قد يسبب تكرار العطل،
لكنها لا تستطيع جعل خوادم Supabase نفسها تعمل أثناء توقف Database/PostgREST.
إذا كانت هذه الحالة تتكرر بعد تركيب V10863، راجع Observability في Supabase:
CPU / Memory / Disk IOPS / Database Connections.
زيادة مساحة التخزين وحدها لا تعالج CPU أو RAM أو عدد الاتصالات.

طريقة التركيب
-------------
1) ارفع ملفات V10863 مكان ملفات النسخة الحالية.
2) افتح reset-cache.html واضغط "تحديث الملفات الآن".
3) سجل خروج ثم دخول.
4) أثناء أول تشغيل والسيرفر Healthy انتظر حتى تظهر البيانات كاملة مرة واحدة؛
   بعدها تصبح هناك نسخة محلية احتياطية لكل مستخدم.
5) اختياري لكن موصى به: عندما تكون حالة المشروع Healthy شغّل
   supabase_stability_v10863.sql في Supabase SQL Editor.

اختبار الحماية
--------------
- افتح النظام وهو Healthy وتأكد من ظهور البيانات.
- بعد نجاح المزامنة ستُحفظ نسخة محلية تلقائيًا.
- إذا تعطل Supabase لاحقًا سيظهر شريط:
  "السيرفر غير متاح مؤقتًا — يتم عرض آخر بيانات محفوظة"
  وتبقى المشاريع والعمال والتكتات والسجلات ظاهرة.
- عند رجوع Supabase سيعيد النظام المزامنة تلقائيًا.

ملاحظة
------
إذا لم يسبق للجهاز أن نفذ مزامنة ناجحة إطلاقًا، فلا توجد نسخة محلية يمكن عرضها أثناء أول عطل.
بعد أول مزامنة ناجحة تعمل الحماية تلقائيًا.
